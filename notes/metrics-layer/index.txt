1d:T667,<p>A metric is more than a formula: population, event, time window and owner. Store definitions as metadata that people and programs can both read, and let a query engine compile them - the post’s platform did this on BigQuery with 100+ reusable definitions. Self-service works only when the shared path is easier than writing another private SQL query; discoverability and ownership are the actual product.</p>
<p>A definition record wants at least:</p>
<pre><code class="hljs language-yaml"><span class="hljs-attr">metric:</span> <span class="hljs-string">order_conversion_rate</span>
<span class="hljs-attr">population:</span> <span class="hljs-string">exposed_users</span>        <span class="hljs-comment"># who is in the denominator</span>
<span class="hljs-attr">event:</span> <span class="hljs-string">order_completed</span>           <span class="hljs-comment"># what counts as success</span>
<span class="hljs-attr">window:</span> <span class="hljs-string">7d</span>                       <span class="hljs-comment"># attribution window after exposure</span>
<span class="hljs-attr">owner:</span> <span class="hljs-string">growth-team</span>               <span class="hljs-comment"># who answers questions about it</span>
</code></pre>
<p>Gotchas: changing a definition is a breaking change - version it and restate history, or dashboards silently disagree with last quarter; a metric without a named owner rots; and backfills must be reproducible, so compile from the same metadata rather than hand-editing historical numbers.</p>
