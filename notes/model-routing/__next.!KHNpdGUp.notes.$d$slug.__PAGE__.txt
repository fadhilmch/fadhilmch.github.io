2d:T615,<p>Model routing is the choice of which deployment serves each model call. Route by workload, not by agent: short structured calls (classify, detect language, filter) and long writing calls want different reasoning effort, timeout and fallback. Each route is a primary plus an optional fallback.</p>
<p>Defaults that worked for me:</p>
<ul>
<li>Deployment name, model name and reasoning effort per slot in configuration. Timeouts and retries in code, because they follow the request time budget, which is the same in every environment.</li>
<li>An empty fallback switches the fallback off for that route.</li>
<li>Always set the model name, even when it equals the deployment name. The prompt file (<a href="/notes/prompt-per-model/">[[prompt-per-model]]</a>) and the request parameters follow the model, not the deployment.</li>
<li>Validate settings at startup. A typo in an effort is a 400, and a 400 does not fall back (<a href="/notes/circuit-breaker/">[[circuit-breaker]]</a>), so it breaks the whole route.</li>
<li>Write the deployment that answered, the route and the effort sent on the LLM span (<a href="/notes/traces/">[[traces]]</a>).</li>
</ul>
<p>Gotcha: two routes can point at the same model. They are still two routes, with their own breaker and their own time budget (<a href="/notes/time-budget/">[[time-budget]]</a>).</p>
