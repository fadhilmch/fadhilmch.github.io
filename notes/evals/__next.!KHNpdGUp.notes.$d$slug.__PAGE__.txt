2d:T4e4,<p>A fluent answer proves nothing, so evaluate the loop rather than the vibe. Compare relevance, retrieval recall, groundedness and latency against a baseline, and read examples next to the scores: grounded, useful and found-the-right-document are three different failures. Offline golden sets give controlled comparisons; production feedback shows what the set missed, and a thumbs-down needs investigation before it means anything. My workflow produces a report for engineers rather than an automatic gate - a choice, not a rule.</p>
<p>When a score drops, the fix depends on which failure it is:</p>

























<table><thead><tr><th>Symptom</th><th>What it means</th><th>Where to fix</th></tr></thead><tbody><tr><td>Right document, wrong answer</td><td>Groundedness</td><td>Prompt/model</td></tr><tr><td>Expected source missing</td><td>Retrieval recall</td><td>Chunking, index, query</td></tr><tr><td>Correct but useless</td><td>Relevance</td><td>Task framing</td></tr></tbody></table>
<p>Always read a handful of raw examples next to any aggregate number - a metric that moved without an example you believe is a mystery, not progress.</p>
