2d:T581,<p>BM25 scores a chunk by adding, over the query terms, IDF times a saturating term frequency, scaled down for chunks longer than average. Rare terms decide the ranking: one hit on an error code outweighs many hits on a common word. Defaults are k1 = 1.2 (how fast term frequency saturates; one term never adds more than k1 + 1 times its IDF) and b = 0.75 (how much length matters; 0 turns it off). Change them only with a golden set to check against.</p>
<p>Gotchas:</p>
<ul>
<li>No shared word means a score of zero. Acronyms, synonyms and other languages miss, so expand known acronyms and keep both forms in the query (<a href="/notes/query-rewriting/">[[query-rewriting]]</a>).</li>
<li>Scores are unbounded and mean nothing across queries. Never add them to cosine scores (<a href="/notes/hybrid-search/">[[hybrid-search]]</a>) or put a fixed threshold on them.</li>
<li>Sharded engines compute IDF per shard by default, so a small index can rank differently from run to run. In Azure, set <code>scoringStatistics: global</code> and pass a <code>sessionId</code>.</li>
<li>Check how the analyzer splits tokens like “v2.1” or “R&#x26;D”.</li>
</ul>
