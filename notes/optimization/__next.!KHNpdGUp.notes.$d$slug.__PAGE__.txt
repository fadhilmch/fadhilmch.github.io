<p>Gotchas: the model is the easy half, and bad input data surfaces as infeasible at 6am - validate inputs before the solve and keep a fallback plan for solver timeouts; log the optimality gap (best bound vs incumbent), not just the objective, so “the solver stopped” has a number attached; and when a model is infeasible, ask the solver for an irreducible inconsistent subset (IIS) rather than commenting out constraints one by one - CVXPY does not expose one, so go through the solver’s own API (Gurobi’s <code>computeIIS</code>, for example).</p>
