1e:T411,<p>Instrument so a stranger can reconstruct any request after the fact: the question, what was retrieved, the answer, and the configuration in force. Dashboards show a pattern; a concrete replay tells you which component or document to fix.</p>
<p>The three signals answer different questions: metrics say something is wrong (aggregated, cheap, alertable), traces say where (one request’s path), logs say why (the detail at one point). Start an investigation from the metric, narrow with the trace, confirm in the logs.</p>
<p>Gotchas: logs without request IDs are archaeology; record versions - model, index, config - next to every answer, or “what changed” is unanswerable; and high-cardinality labels will bankrupt the metrics bill, so keep label values to a bounded set (never user IDs or full URLs).</p>
<p>Reference: <a href="https://opentelemetry.io/docs/concepts/observability-primer/">OpenTelemetry observability primer</a>.
