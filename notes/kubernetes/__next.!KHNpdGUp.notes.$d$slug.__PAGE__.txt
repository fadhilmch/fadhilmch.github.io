2d:T4f8,<p>Kubernetes stores desired state while controllers keep trying to make the running system match it. A Deployment manages replicas, a Service gives traffic a stable destination, and Helm packages configuration. That mental model is more useful than memorising object names without knowing which controller or traffic path they belong to.</p>
<p>The four objects that answer most questions:</p>

























<table><thead><tr><th>Object</th><th>The question it answers</th></tr></thead><tbody><tr><td>Deployment</td><td>How many replicas, which image, how to roll</td></tr><tr><td>Service</td><td>Where does traffic find the pods</td></tr><tr><td>Ingress</td><td>How does outside traffic get in</td></tr><tr><td>ConfigMap / Secret</td><td>Where does configuration live</td></tr></tbody></table>
<p>Useful when something is wrong: <code>kubectl get pods</code> for state, <code>kubectl describe pod &#x3C;name></code> for the event trail (scheduling, pulls, probes), <code>kubectl logs &#x3C;name> --previous</code> for the crash before the restart. Most “Kubernetes is broken” is a failing probe, a bad image tag, or resource limits - all visible in describe.</p>
