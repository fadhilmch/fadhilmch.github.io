2d:T61a,<p>A follow-up like “and in Poland?” can’t be searched alone, which caps what <a href="/notes/rag/">[[rag]]</a> can find. Rewrite the latest message into a standalone query before search, not after. History given only to the answer model comes too late: the documents were already found with the bare follow-up.</p>
<p>Defaults that worked:</p>
<ul>
<li>Skip the rewrite when there is no history. Nothing to resolve.</li>
<li>Send the dialogue as JSON data in the user message; keep rules in the system message and say “do not answer”.</li>
<li>Return <a href="/notes/structured-output/">[[structured-output]]</a>: the query plus fields like locations, which become filters.</li>
<li>On a parse failure, search the raw message.</li>
<li>Keep codes and acronyms exactly; expand them in code afterwards.</li>
<li>Pass a bounded slice of history (we use the last 10 messages).</li>
</ul>
<p>Gotchas: a generic prompt adds context by default and breaks new questions after a clarifying question, so decide the <a href="/notes/follow-up-types/">[[follow-up-types]]</a> first. An empty history looks like success; check <a href="/notes/conversation-memory/">[[conversation-memory]]</a> before blaming the prompt. Test each type with the real model, more than one sample per case (<a href="/notes/prompt-testing/">[[prompt-testing]]</a>).</p>
