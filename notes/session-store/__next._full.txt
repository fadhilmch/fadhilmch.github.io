20:T627,<p>Keep pods stateless and put the session in a store with expiry, such as Redis. Don’t rely on sticky sessions. One JSON value per session id, written with a TTL (<code>SETEX</code>), read once at the start of a turn and written once after it succeeds.</p>
<p>Defaults and gotchas:</p>
<ul>
<li>Namespace keys by environment, so dev and test traffic can’t read each other’s sessions.</li>
<li>Decide what a missing session means. For a chatbot, a fresh session is fine.</li>
<li>When the store is down, degrade instead of failing (<a href="/notes/graceful-degradation/">[[graceful-degradation]]</a>). A small per-pod cache bounded by size and TTL keeps conversations going, and a <a href="/notes/circuit-breaker/">[[circuit-breaker]]</a> stops every request from paying the timeout.</li>
<li>A per-pod copy is private. After recovery, a pod can write back a session older than what another pod saved. A revision check on write closes that gap.</li>
<li>In redis-py, <code>RedisClusterException</code> is not a <code>RedisError</code>. Catch both, or a cluster that is down at startup escapes your fallback.</li>
</ul>
<pre><code class="hljs language-python">UNAVAILABLE = (RedisError, RedisClusterException, asyncio.TimeoutError)
</code></pre>
