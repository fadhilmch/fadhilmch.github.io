2d:T5fb,<p>A filter is a yes or no test on metadata (country, region, team, date) that runs before ranking. If it drops the right chunk, nothing downstream can bring it back, and nothing raises an error: the search still returns ten chunks and the model answers from the wrong ones.</p>
<p>Bugs I have seen, each silent:</p>
<ul>
<li>One value tagged with two spellings, and the filter sends only one.</li>
<li>Case mismatch. Azure text filters are exact and case-sensitive; a normalizer on the field fixes the whole class.</li>
<li>A clause dropped in a refactor.</li>
<li><code>any()</code> over an empty collection is false, so untagged rows never match a clause like this:</li>
</ul>
<pre><code class="hljs language-text">(country eq 'se') and (city/any(c: c eq 'common'))
</code></pre>
<p>Rules:</p>
<ul>
<li>Test reachability from the data side. For every document, build the real filter for its own scope and check that it matches.</li>
<li>Give temporary alias tables a check that says when an alias matches nothing and can go.</li>
<li>Record the exact filter on the retrieval span (<a href="/notes/traces/">[[traces]]</a>).</li>
<li>For <a href="/notes/vector-search/">[[vector-search]]</a>, prefiltering keeps k results if they exist; postfiltering can return fewer.</li>
</ul>
